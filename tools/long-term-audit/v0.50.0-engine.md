### 普通图层的专用方法丢失

下面用 `layer(layer_class = ...)` 构造带可观察行为的点层。其 `setup_layer()` 保留数据首行，随后调用父方法，仍走通常的 ggplot2 映射流程。

```r
suppressPackageStartupMessages(pkgload::load_all(".", quiet = TRUE))
points <- data.frame(x = c(0.1, 0.2), y = c(0.1, 0.2))
seqs <- data.frame(accver = c("a", "b"), length = c(100, 80))
parent_layer <- ggplot2::geom_point()
first_row <- ggplot2::ggproto(
  "FirstRow", parent_layer,
  setup_layer = function(self, data, plot) {
    parent <- ggplot2::ggproto_parent(parent_layer, self)
    parent$setup_layer(utils::head(data, 1L), plot)
  }
)
points_layer <- ggplot2::layer(
  geom = "point", stat = "identity", position = "identity",
  mapping = ggplot2::aes(x = x, y = y), data = points,
  layer_class = first_row
)
grDevices::pdf(NULL)
ordinary <- ggplot2::ggplot_build(ggplot2::ggplot() + points_layer)
chord <- ggplot2::ggplot_build(ggchord(seqs) + points_layer)
invisible(grDevices::dev.off())
c(ordinary = nrow(ordinary$data[[1L]]), chord = nrow(chord$data[[1L]]))
```

**观察结果**为 `ordinary = 1, chord = 2`。注册器遍历所有层，先用 `reconstruct_layer()` 重建，再判断 `ggchord_type`。重建调用给出了 geom、stat、position、mapping 和若干参数，但省略了原有的 `layer_class`。这个反例的可见影响是多绘制一个点。修复时可比较这两个点层的记录及坐标，并检查重复使用同一个图层对象时的隔离性。[注册与重建](../../R/layer-registry.R)

ggplot2 的 `layer()` 公开列出 `layer_class`，其参考手册同时说明 Layer 基类属于内部实现。这里使用专用方法定位重建造成的信息丢失。稳妥的目标是让普通图层原样交给 ggplot2，对外扩展入口以 Geom、Stat、Position、Coord、Scale、Guide 的职责为基础。引用的在线手册为 4.0.4，本机复现为 4.0.3。[layer()](https://ggplot2.tidyverse.org/reference/layer.html) · [Layer 生命周期](https://ggplot2.tidyverse.org/reference/Layer-class.html)

### 覆盖分组、坐标单位与窗口边界

用同一条长 10 bp 的序列、一个宽 10 bp 的闭窗口和两条重叠注释，检查源分组、比例分母和映射阶段。以下为现行调用。

```r
seqs <- data.frame(accver = "A", length = 10L)
intervals <- data.frame(
  accver = "A", start = c(3L, 5L), end = c(6L, 8L), type = c("a", "b")
)
coverage_plot <- function(reference, records, binwidth, mapping = NULL) {
  ggchord(reference) +
    geom_seq() +
    geom_track_bar(
      mapping = mapping, data = records, stat = "coverage",
      binwidth = binwidth, track = position_track("cov")
    ) +
    coord_collinear()
}
stat_rows <- function(p) {
  export_ggchord_layout(p, data_stage = "statistic")$track_statistics[[1L]]
}
stat_rows(coverage_plot(seqs, intervals, 10L))
stat_rows(coverage_plot(seqs, intervals, 10L, aes(group = type)))
stat_rows(coverage_plot(seqs, intervals, 10L, aes(fill = type)))
```

**实测。** 两条记录的并集是 3–8，覆盖率 6/10 = 0.6，平均深度 (4 + 4)/10 = 0.8。后两种写法各返回两行，每组的覆盖率和平均深度均为 0.4。按类别堆叠的高度 0.8 包含重复覆盖。候选语法中，按类型比较可显式映射 `group = type`，按总覆盖率着色则用 `aes(fill = after_stat(coverage))`。后者在统计完成后才取得填色值。按同一窗口与分组将柱换线时，建议同时核对数值、贡献行和短末窗边界。[分组语义](https://ggplot2.tidyverse.org/reference/aes_group_order.html) · [现有窗口与来源](v0.29.0-layer-grammar.md#从区间追到窗口)

**已复现的单位缺陷。** 给上面的 `seqs` 增加 `sequence_unit = "aa"`，输入只含 A 上的一条 3–6 区间，显式声明 `sequence_unit = "bp"`，以 4 为窗宽运行同一探针。现在计算成功，给出 1–4、5–8、9–10 三窗的覆盖率 0.5、0.5、0。相同数值在一致单位的输入上才有解释。导出中 `width` 可取柱形的 0.9，各窗实际分母为 4、4、2，可由 `window_end - window_start + 1` 重建。建议在统计前对参考、区间及显式窗口核对单位，冲突时报出数据来源，需转换时使用登记的投影。建议明确导出源端点、单位、实际分母及贡献记录。Dotplot 已有可供复用的检查。[覆盖输入](../../R/stat-track-coverage.R) · [单位检查](../../R/data-contract.R) · [Dotplot 调用](../../R/coord-dotplot.R)

**实测的显示范围。** 换成长 10 的参考、3–6、4–5、10–10 三条区间和窗宽 4，完整序列上三个窗的覆盖率均为 0.5。分别在现行图上使用 `coord_collinear(xlim = c(3, 7), clip = "on")` 或 `scale_seq_position_continuous(limits = c(3, 7))`，三条统计值均保留。单独设 `scale_track_value_continuous("cov", limits = c(0, 0.2))`，统计表仍有三行，几何准备记录均标为 `outside_scale_limits`。分别验收数据分析范围、序列轴刻度、轨道数值越界行为、Coord 视口与自动适配。这些操作发生的阶段会改变导出的含义。[轨道数值与越界报告](../../R/layout-track.R)

**聚焦重算的手算判据，待确认。** 对同一输入聚焦源 3–7，应明确用户选择的是哪一种操作。

| 操作 | 可见或新建窗口（源位置） | 预期分子/分母 |
| --- | --- | --- |
| 只缩放视口，显示原先算好的格子 | 原 1–4、5–8 各有一部分可见 | 原值 2/4、2/4 |
| 用原网格与查询区间的交集重算 | 3–4、5–7 | 2/2、2/3 |
| 以局部位置 1 为原点重新分窗 | 3–6、7–7 | 4/4、0/1 |

建议结果保留源序列、源与局部的窗口两端、窗口 ID、分母和来源。单碱基、跨起点及多段记录应按实际有效段计算。已观测组的空窗可以给零覆盖。无观测组、全缺测组需要输入提供观察范围，不能单凭空表或轨道名推断。多个相交的查询窗口可各自解释，同一源记录在两个窗口都出现时应保留双重归属。对于双端 HSP，现有 focus 同时裁两侧时可能线性插值并取整，输出带 `.alignment_projection = "linear"`。求单侧原始 HSP 区间覆盖可直接裁该侧端点。声称逐位置精确对齐需要相应分段或字符证据。[聚焦与投影](../../R/focus.R) · [定量输入聚焦](../../R/focus-track.R)

### 手动配色的最终输出

**实测。** A 长 1,000 bp，三个特征依次为 CDS 101–300（+）、promoter 201–250（+）、CDS 701–800（−）。构造 `p <- ggchord(seqs) + geom_seq() + coord_circular() + geom_feature(aes(fill = type), data = features)`。用相同命名向量 `c(CDS = "#417D85", promoter = "#D87945")` 分别作为 `scale_fill_manual(values = ...)` 和 `scale_feature_fill_manual(values = ...)` 的输入。

普通标度的 `ggplot2::ggplot_build(p + scale)$data` 在特征层里有两个指定的 fill，最终 gtable 和绘制结果仍出现默认紫色 `#993366`。两张图分别调用 `ragg::agg_capture(width = 760, height = 600, res = 100, background = "white")`，`print()` 绘制后读取捕获像素，按两个指定十六进制颜色精确计数。普通标度为 **0、0**，专用标度为 **5,127、1,073**。这些数值含整图与图例像素，供重放本次设备对照。迁移验收应分别检查图形本体、图例键和标题，确保两者都随用户标度改变，再切换专用入口。颜色之外，区间的箭头、块、带端帽线等形状也要单独验证类别映射和图例。[特征几何](../../R/geom-feature.R) · [标度拟去向](v0.50.0-api-inventory.md)

### 分面的数据分派、位置和物理测量

**实测一，数据归属。** 使用同一条长 1,000 bp 的 A，S1、S2 分别只含 100–200、500–700 的一个特征。添加 `geom_seq()`、`geom_feature(shape = "block", ...)`、`facet_wrap(vars(sample))`。给两个区间映射可区分的填色后检查 `ggplot_build()` 中的面板表及各特征所在面板，再绘制 gtable。骨架在两个面板都出现，每条注释只在自己的面板出现。按 S2、S1 顺序重排记录，移除填色映射，分别从图层 `data` 或构造器 `feature_data` 传表。默认坐标、圆图和直线图均保留 S1、S2 的面板归属。几何生成后会依据源行回填原始列，ggplot2 因此能取得 `sample`。[图层准备](../../R/ggchord-build.R) · [源行回填](../../R/layer-input.R) · [原生构建](../../R/ggchord-frame.R)

**实测二，跨面板分道。** 将 S1 和 S2 各自唯一的特征都设为 A 的 101–300、正链。在圆图的方块特征层使用 `position = position_feature_stack()`，比较合图加 `facet_wrap(vars(sample))` 与分别绘制 S1、S2 的结果。合图中 S1 在第一道，S2 向外多走一道。两张单样本图都在第一道。实际面板归属正确，用户仍会读出原始数据没有的道位差异。候选验收为先确定面板和来源，再在该面板内统计、分道、避让和测量。新增 S3 后，原有样本应保持相同的特征来源及独立道位。设备可用空间变化可能调整文字布局。

**当前界限与候选验收。** 原生轨道、Dotplot、Radial 坐标、Fusion 子图及自动适配对非单面板有显式限制。当前实际面板尺寸测量只处理单一 panel。ggplot2 原生 `facet_wrap()` 和 `facet_grid()` 的常用入口可以沿用，领域层需界定共享骨架、按样本分派的观测，以及双端记录按哪一端分面。建议对同度量的样本分面默认共享量尺，对 Fusion 独立图按需声明共享训练域。圆图局部轨值和屏幕 y 的关系须先定案，才可解释自由量尺。本机用原生 ggplot2 对照两个样本的单个观测值 0.1 和 0.9。默认分面共用训练范围 [0.1, 0.9]，只给每面板自由 y 范围时分别训练为 [0.1, 0.1] 与 [0.9, 0.9]。候选面板还需核对共有参考骨架每面板一份，以及无样本键的观测层能给出可操作提示。[轨道](../../R/track-grammar.R) · [Dotplot](../../R/coord-dotplot.R) · [Radial](../../R/coord-collinear.R) · [Fusion](../../R/fusion.R) · [自动适配](../../R/adaptive-layout.R) · [物理测量](../../R/render-context.R)

### 原生统计的变换顺序与映射范围

最近几轮在 ggplot2 4.0.3 单独构建了两个对照。候选引擎需要逐层声明作用域，随后才能判定一个 ggplot2 统计可否安全地复用于某个轨道。

| 上游探针 | 已观察结果 | v0.50.0 待核对 |
| --- | --- | --- |
| 同一组有两个 y 观测 1、100，运行 `stat_summary(fun = mean) + scale_y_log10()` | 构建的 y 为 1，即先取对数再求均值。先求源均值再取对数会给出约 1.703291 | 领域覆盖按源序列单位计算。原生统计与尺度变换、limits、越界处理的次序应与其声明相符。 |
| 同一位置的两面板观测数分别为 1 和 3，计数层用 `aes(y = after_stat(count / sum(count)))` | 两面板的 count 为 1、3，统计后映射得到 0.25、0.75 | 每面板独立调用完整 build 会使两个分母均变为本面板计数，结果为 1、1。需区分源序列、面板及组内的统计范围与汇合后整层表达式的求值范围。 |

新引擎也需分别核对三个映射阶段。映射到原始列的分组应在统计前确定，`after_stat()` 可读取计算列，`after_scale(fill)` 应读取本层所属标度的最终颜色。让一层使用离散 fill、另一层使用连续 fill 时，改变其中一个域需核对另一层的几何与图例。全局类别颜色可由本层固定黑色覆盖，兄弟层保持数据映射。同层同时声明固定值与局部映射的冲突另行诊断。前文原生扩展层“1 个点变 2 个点”的探针继续用于核对外部图层本身的行为。[上游映射阶段](https://ggplot2.tidyverse.org/reference/aes_eval.html) · [上游 Layer](https://ggplot2.tidyverse.org/reference/Layer-class.html)

### 新语法教学与旧图保真回放

**配方核对。** 新圆图示例从骨架零偏移向外分道，旧旗舰 `position_plasmid()` 从 −0.1 向内分道。新语法教学可以用前一种意图。比较前后视觉保真时，应让两次运行采用相同起点和方向。共线性旧旗舰还采用自动方向及居中对齐。真实例中的四条最终都为正向，另需显式翻转一行，才能检出“源坐标最靠前”和“画面最左”两种标签选择的差异。既有五图计时脚本覆盖基本图、弦图、圆图、共线图和 Dotplot，六种投影与组合的回放可复用现有 Radial、Sankey、Fusion 旗舰。建议记录基线提交、输入与配方的版本或校验值、尺寸、字体、设备，以及来源、端点、道位和有意改变的外观。[圆图和共线性配方](../documentation-examples.R) · [旗舰生成规则](../../data-raw/generate_flagship_data.R) · [其余旗舰](../site-flagships.R) · [五图计时](../profile-showcase-render.R)

**Dotplot。** 当前旗舰输入有 4 条参考序列、32 条 HSP，query 和 subject 各只出现 3 条不同序列。仅设 `gap` 时导出的轴各含 3 条序列，显式给两轴完整序列集合时各含 4 条，保留额外 7 个空序列对。空格的可核对含义是本输入没有该组合的命中。二维统计中点可能为半整数，例如 5,000.5，当前草案示例的分格公式将它归入第一格。候选验收要让计算的归格与原始 HSP 中点的投影一致，明确半整数边界的归属，分别检查反向轴及短末格的边缘。格计数和贡献的 HSP 身份应能从统计结果查回，避免由用户重写分格公式。[轴与端点](../../R/coord-dotplot.R) · [工作流](v0.50.0-workflows.md)

会话中两张对照图作为现行代码的示例档案，见[工作流](v0.50.0-workflows.md)。一次交互核对刷新了 Git 忽略的 `Rplots.pdf`。图像验收应从固定输入、配方和设备重放，不能取用此 PDF 或临时试绘图作为基线。此前 15 对基准图、178 张教学图和 13.372 秒的计时仍对应各自归档提交。后续分面和新语法的实际速度及保真程度需在实现后测量。

## 拟议引擎及数据所有权

一次绘制从图对象中取一份有序图层清单。清单记录每次出现的图层和所属面板，区分 ggchord 组件与普通 ggplot2 层。几何依赖通过来源、坐标框架或物理占位显式连接。实现优先复用现有数值求解、轨道统计、投影及字体度量。下面列出拟切换的内部边界，名称只用于描述工作。

| 阶段 | 输入 → 输出 | 允许共享的范围与反例 |
| --- | --- | --- |
| 准备 | 构造器及图层表、函数或公式、映射、坐标与层顺序 → 本次构建的所有者清单、来源表及本地行号 | 函数数据一次绘制只求值一次；独立绘制重新求值。两层恰好含相同行值，仍可能来自两个显式输入。普通层保留类、方法、映射环境、参数与层序。 |
| 源域统计 | 本地序列、真实区间、单位、分组、焦点窗口和适用的映射 → 统计表、来源成员及遗漏说明 | 对同一份已解析输入，在一次渲染的设备修正中复用。每个统计结果保留有依据的来源成员。合并覆盖与平均深度各用自己的分子，分母使用该窗口实际长度；显示副本不重复计数。 |
| 位置和投影 | 来源结果、骨架及各层 Position → 端点、局部路径、序列框架、实例路由及图层几何 | 共线、垂直、环形、径向和 Sankey 保留各自方向、单位和反向映射。Dotplot 的两轴独立。初稿仅允许显式共享实体位置。复审建议验证来源、实体和面板内实例的唯一匹配后也可传递锚点；存在歧义时要求显式选择。 |
| 物理布局 | 框架、guide、文字样式、当前设备、面板范围 → 字框、道与引线、轨道边界、可见状态和测量依据 | 引线需要最终障碍物，毫米轨道需要最终面板范围。允许复用与候选位置无关、当前字体和当前设备下的字形度量。旋转、物理长宽或样式变化后重新定位与检验。 |
| 绘制及查询 | 几何与已训练样式、gtable 和可选阶段捕获 → 设备图形、布局、诊断、可追溯导出 | ggplot2 负责视觉标度及阶段映射，Geom 负责形状与固定样式。共享干线必须在最终可见样式已知后决定。Fusion 持有子图最终框架和毫米边界，跨面板连接从各自的来源区间投影。 |

**按 ggplot2 的扩展职责实现。** 一个可独立计算的覆盖窗口交给 Stat，返回窗口坐标、计数和可追踪成员；分道与偏移交给 Position，读取本层位置参数；区间带和点交给 Geom 使用已经映射的样式绘制。Coord 提供此面板的序列框架、局部方向和投影，Scale 处理数值/样式域及用户覆盖，Guide 描述刻度与图例，Theme 提供非数据外观。对需要多层信息的关联，可以由所有者清单在这些操作之间提供显式依赖。例如一个带有物理轨道和多层标签的圆图，轨道边界会影响引线路径，单个 Geom 的逐行绘制阶段拿不到完整障碍物。应在面板布局层联合求解，再将各自几何交回各图层，保留用户叠放顺序和原生 guide。第三方 Geom/Stat 的接入先选一项有明确定义的输入和输出做端到端验证。[现有布局阶段](../../R/layout.R) · [图层职责](https://ggplot2.tidyverse.org/reference/layer.html)

**来源与单位贯穿每一步。** 图层出现 ID、文件记录、构造器来源行、解析后图层行、聚合成员和显示实例各有作用域。装饰几何的来源可缺失，缺测、遗漏和多对多映射显式保留。序列单位为 bp 或 aa，原始区间按各自单位的一基闭区间表示；投影边界、旋转角、布局数据单位和设备毫米各自明确。普通视觉映射的开始、统计后与标度后三阶段由 ggplot2 处理，参与端点定位的角色必须在所需阶段已有值。[来源与单位](../../R/layout-contract.R) · [映射求值](https://ggplot2.tidyverse.org/reference/aes_eval.html)

**直接布局与目标设备各有调用者。** 直接布局查询、按阶段导出以及真实设备绘图应共用一次性准备入口。需要已训练样式时请求 build；需要物理证据时请求目标设备。现有 `data_stage` 约定中的 source 为适配后的原始层输入，mapped 为角色映射后、层变换前的表，statistic 为可用统计结果，geometry 按组件组织。原生 track 在 ggplot2 内完成映射，mapped 可以为 `NULL`。新接口即使改名也要解释每张表的形成时刻。用户只能从实测记录读取真实面板尺寸；预估和未能测量的状态需如实返回。[阶段导出](../../R/layout-export.R) · [目标尺寸诊断](../../R/diagnostics.R)

目标实现以一次绘制的临时状态组装完整结果，成功后才更新可复用布局。输入函数或统计失败应保留原始错误和所属图层并清理当次捕获。嵌套求解退出时恢复前一层设备上下文，发生错误时同样恢复。对于尺寸外推失败，可丢弃候选并回到上次有效测量，继续受限迭代。达到预算仍未收敛时报告面板测量状态、几何估计和收敛状态；guide 空间不足保留具体诊断。复核这些路径时先让一个带错误数据函数的子图失败，再修正输入独立重绘，核对另一个图和外层设备仍能正常使用。[当前上下文恢复与尺寸修正](../../R/render-context.R) · [Guide 排版](../../R/guide-layout.R)
