## 目标与非目标

将 ggchord 整理为 ggplot2 风格的基因组比较与注释可视化框架。保留 chord、circular、
collinear 三类模式，共享合理的数据、图层和输出契约。依次优先保证生物学与坐标
正确性、行为可追溯、清晰语义、生态兼容、组合扩展，再考虑性能与接口数量。

本计划不预先决定 gene/feature 合并、getter 删除、colour/color 别名去留或重导出
裁剪；也不因函数长、参数多、名字相似或零词法引用就认定设计错误。
不增加第四类绘图，不承诺交互绘图、更多定量 geom、多 contig 或其他研究池功能。

## 首版的三个工作批次

1. **审计基线与覆盖**：复核附件脚本并补足遗漏识别；生成导出、S3、内部具名函数、
   ggproto/匿名方法、别名、形参和间接使用清单。记录审计所依据 SHA 与工具局限。
2. **证据、契约与目标方案**：逐 API 和参数补充实际行为、默认、单位、NULL/NA、
   验证路径、坐标支持、替代设计和迁移建议；提出目标架构及需要用户选择的事项。
3. **首批实施方案与局部验证**：优先为 F01/F02 构造最小反例，确认影响后提出修复；
   其余改名、合并、弃用或删除先提供成对调用和影响说明，再按已确认范围实施。

执行进展、实际证据与尚未完成的范围见 [v0.16.0](versions/v0.16.0.md)。
静态盘点和局部修复不能替代全量参数语义审查或正式发布验收。

## 新 API、迁移与验证门槛

新增 API 必须有真实可复现场景、直观职责、现有组合不能覆盖的缺口、明确输入输出与
坐标错误契约、跨模式和图层独立性、最小运行示例与必要回归，以及无需堆叠专有特例
的扩展方式。必要的新 API 可以提出，不因报告提及就成为已决定的功能。

任何破坏性方案先说明旧调用、新调用、替代方案、受影响用例、默认变化、错误提示
和删除版本；尚未选择的名称或版本明确标为待确认。实际完成后同步 NEWS、相关
roxygen/Rd、迁移文档和版本记录，不能将计划预写为 NEWS 的已实现事实。

普通开发只使用相关最小脚本、代表性 build 或直接几何断言，不运行完整 testthat、
build/check、vignette 或设备矩阵；正式发布授权后执行仓库规定的全部发布验收。
不以私有字段、精确浮点、固定秒数或等价语法穷举锁定实现。各阶段交付均说明：
实际修改、默认变化、旧调用影响、替代写法、验证证据、尚存 H/D 和下一步取舍。
