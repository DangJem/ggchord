## 2026-10-29 计划审计与取舍

用户授权审计、调整 v0.15.0/v0.16.0 并继续开发，只有开发压力较小时才合版。
审计结论为**不合版**：v0.15.0 本身包含数据身份、坐标和多表关系的多个阶段；
v0.16.0 另需设备度量、资源分配和三种 coord 的几何适配，不能视为少量附加功能。

- 保留“已有结果转成图”的目标，复用 v0.14.0 已发布的 `as_ggchord_*()`、
  `focus_ggchord_data()`、ribbon utilities 和布局建议，不另建第二套转换器。
- 命名集合采用命名列表，显式交给各图层，不让准备器猜测图层、scale 或数据角色。
  genome → contig 先保留为元数据关系；`accver` 全局唯一，不拼接虚假连续基因组。
- 稳定 ID 直接来自输入；缺失 ID 不用行号伪造。重复 ID 可表示分段特征，
  多 Parent 保留为列表；具体操作负责检查 ID 在其上下文中的歧义。
- 常见 synteny 表先用显式列映射适配；不承诺一个能自动识别所有软件方言的 reader。
  GenBank/GBFF 需单独选择成熟可选解析器并核对复合位置，而非临时手写不完整解析器。
- 删除将“非平面交叉下界”当作 ribbon 视觉质量指标的计划；抽象图性质不足以
  代表实际区间几何。当前提供有向 pair 计数和可选的既有优化建议。
  自动推荐 bundling bins/密度阈值暂不承诺，需先有可信定义及使用案例。
- 外部比对工具只在文档中说明输入格式与显式准备流程。核心包不承担通用可执行文件
  检测器、安装器或运行器；小型纯 R 比对适配评估暂不作为本版交付项。
- 本次增加的必要正确性内容为：跨步骤来源追溯、默认无损与方向保护、合法单碱基区间
  一致性。这些是准备工作流的基础，不新增绘图 grammar。

## 第一阶段：已实现

### 报告式准备与集合

新增 `prepare_ggchord_data()`，输出 constructor 三表及命名 `features`、`links` 集合。
`mapping` 复用既有列转换，保留来源 metadata；输入文件先用对应 reader 导入，
不根据扩展名自动导入。`genome` 列如存在须完整；不推断分组或重命名 accession。

默认只转换、验证，不清洗、去重、截断、聚合、改序或翻转。显式 `steps` 按
clean → filter → deduplicate → merge → bundle → optimize 的固定顺序执行；
每步继续可独立调用。clean 只影响 constructor 三表，其余操作只影响主 ribbon 表，
命名集合始终独立。布局优化只返回建议，不应用到图形。

报告包含转换来源、导入格式/文件/每文件行数、前后验证、命名 feature 的边界与 ID
问题、命名 link 的验证、各步骤报告、每个输出 ribbon 对应的原始输入行、pair 计数
和可选布局建议。去重等删除关系可在对应步骤报告中查到；步骤行号针对该步骤输入。
默认关闭二次方级的近重复验证；显式请求去重才执行所选去重策略。

准备流程的 clean 默认保留方向端点 `reversed_interval = "keep"`，区别于独立
`clean_ggchord_data()` 的历史默认 `"sort"`。显式 sort 与后续 deduplicate、merge、
bundle、optimize 冲突时给出错误与 keep 替代写法，防止正反向连接被合并。
该检查先归一化参数缩写；已排序输入的 direction 与端点不一致时同样拒绝，
不能通过再次 clean 覆盖方向来绕过。

`gene_data` 保持方向性基因契约；未知链和双向通用 feature 放入 `features`，
不通过把未知链填成 `+` 来绕过验证。结构性转换错误立即报错；已转换表中的未知
序列、越界等保留在报告，不默认修复。稳定 parent-child/domain 操作仍属第二阶段。

### 导入与身份

- 新增 `read_bed()`：BED3–12，0-based half-open → 1-based inclusive；BED12
  保留并验证 blocks，生成 `segments`。保留原始坐标/显示字段，不自动套用颜色，
  BED name 不自动成为唯一 feature ID。零宽 insertion 和 BED12+ 扩展明确拒绝。
- 新增 `read_paf()`：保留 query/target 角色和相对方向，负链 subject 端点递减；
  保留原始坐标、tags 和 mapq 来源。`pident` 是已报告 matches/block length 的比例，
  不声称重新比对或精确重算；mapq 255 输出缺失值并保留原值。
- `read_gff3()` 暴露解码的 `feature_id` 与 `parent_ids` 列表，先分 Parent 再解码，
  保留重复分段 ID；新增 `unstranded = "keep"`，用于 nondirectional feature。
  旧默认 plus 不改变，`source_strand` 保留原始输入；再次转换时原始字段如冲突会
  按既有 metadata 前缀规则保留，转换报告可追踪其名称。
- 所有 reader 记录导入文件及每文件输出行数；转换器保留上游导入和转换记录。
  新格式依据 UCSC BED 和 PAF 规范实现，来源在 roxygen 中列出；没有复制解析代码。

### 目标 locus 与区间正确性

新增 `find_ggchord_loci()`：按明确 `feature_id` 找到目标，按链方向分别扩展
upstream/downstream，裁剪到全序列范围，报告目标边界、裁剪和来源行。
未知链只允许对称扩展；歧义 ID、蛋白坐标或跨原点区间不能被猜测为普通 locus。

现有 `focus_ggchord_data()` 已支持同一序列多个独立窗口和唯一 `locus_id`，
新 locus 结果直接复用它。每个窗口作为独立序列输出；同排多窗口、缺口拼接和局部
翻转仍在第三阶段，不能把已支持的独立窗口误写成尚未支持。

修复 `clean_ggchord_data()` 把 `start == end` 的合法 inclusive 区间误当零长度
删除的问题。完全越界区间在 clip 前报告并删除，不在边界制造虚假 1 bp；部分相交
裁剪后仅余 1 bp 仍保留。不改其历史排序默认，也不扩大为完整清洗重写。

## 第二阶段：仍待实现

先独立设计数据关系和失败语义，再开展以下已确认范围；本次未声称完成：

1. 同源簇到 gene links 的转换：检查多拷贝/一对多、比较对象和连接规模；不默认
   生成不可控笛卡尔积，不把同源组 membership 伪造成 alignment identity。
2. 蛋白/核苷酸坐标投影与父子 domain 模型：显式 CDS segment、链、phase、遗传密码、
   不完整 CDS 及跨片段投影；不能把所有蛋白坐标统一乘三。
3. GenBank/GBFF 与可选 Biostrings 适配：保留复合位置、未知长度、原始 metadata；
   缺少可选依赖时给出可执行替代方向，不强制新增运行依赖。
4. 更完整的 genome → contig 关系验证及针对真实输入的工作流说明。当前元数据支持
   不等同于已实现跨表层级对象或自动 genome 排列。
