## 范围与接口

- 专用 `coord_circular()` 表达单序列闭合圆图及带缺口的线性化圆图，不将其塞入
  `coord_chord()` 的退化分支；与现有 ggplot2 的 `aes`、scale、geom、position、
  coord、theme 职责保持一致。
- `position_feature_stack()` 只分配逻辑 lane：显式 display priority 优先，
  其后按 feature span 由长到短，并复用最近的无冲突 lane。`coord_circular()`
  管理最终物理 track、半径、可变宽度和跨图层障碍；track 0 为可见 backbone。
  不以质粒名、feature 名称或颜色决定 lane。
- `geom_feature_plasmid()` 使用与 gene/feature 共享的 interval、local frame 和
  shape 工厂。单个 biological feature 的多 segment 共用 track、方向和唯一标签；
  gap、分段色、连续 join 和 cleavage marks 在几何阶段表达。point feature 是
  backbone tick；短方向 feature 只压缩沿序列方向的 body/head，不改变数据坐标
  或名义径向宽度。
- 方向由 feature 自身 `directionality` 决定；支持无方向、正向、反向及双向。
  `arrow`、`compact_arrow`、`promoter_arrow`、`primer_arrow`、`marker`、
  `block`、`capped_line`、`chevron`、`lollipop` 等形状不按名称强制配色或方向。
  `capped_line` 表达源数据明确的线性／无填充区间。
- `geom_seq()` 提供 single/double/band backbone；`geom_seq_center_label()`、
  轴刻度、`view_ggchord()` 的自动尺寸和 `export_ggchord_layout()` 的资源记录
  服务圆图，但显式导出尺寸与用户 scale 始终优先。
- 迁移：旧 `seq_id` 改用 `accver`；旧 `geom_ribbon()` 改用
  `geom_link_ribbon()`；`geom_gene()` 如需旧版隐式向链两侧偏移，应显式写
  `position = "strand"`。v0.13.0 未发布，用户可见的首次删除版本为 v0.13.1；
  `NEWS.md` 保留 v0.12.0 当时的弃用计划作为历史记录。

### 图层独立性与共同布局的职责边界

- feature、feature label、restriction-site 和 primer 继续是独立图层：各自拥有
  `layer_id`、`data`、`mapping`、固定样式、guide 语义和可见性；一个 geom 不读取、
  改写或合并另一个 geom 的用户数据，也不得按图层添加顺序获得优先权。
- 图层独立不等于最终设备空间互不相干。各 geom 在第一阶段只向
  `coord_circular()` 提交自身的真实 root、自然文字锚点、实测 bbox、允许的候选
  band/slot、引线路径类型和不可跨越的几何包络；圆形坐标在所有图层完成后，作为
  唯一的共享物理资源管理者联合分配轨道和走廊，再把结果分别回写到原图层几何。
  这与 scale 统一训练多个图层、coord 统一变换所有图层属于同一层级的全图职责，
  不把跨图层避让塞进任一 geom 或 Position。
- Position 仍只处理数据空间内、可在不知道设备和其他图层时确定的局部 lane；
  coord 的 annotation registry 只处理最终字体和设备空间才可确定的碰撞。用户提供的
  scale、geom 样式和图层数据始终优先，registry 不能改变 feature 的生物学坐标、
  restriction 切点或 primer 区间。
- 联合求解必须对注释类别和图层顺序对称；类别只决定合法候选及路径语义，例如
  restriction 允许直线／单折线、内部 feature 文字沿弧排列，而不能决定“谁先固定”。
  当前外圈已改为按真实 root 顺序的共同候选序列；隐藏优先级和合法端口仍可因类别
  不同，但求解先后不再由图层类型决定。若未来公开布局控制入口，应归于
  `coord_circular()`；v0.13.1 只维护内部协议，不提前暴露 v0.16.0 的通用
  track/ring API。

## 圆内轨道与 feature 文字

- 圆内 track 是有内外边界和实际径向宽度的封闭环带。宽度由该轨最大实测需求
  决定；feature polygon、圆内文字及其字符包络都必须完整留在所属环带中，不得
  跨越 track 边界借用相邻环带的空间。
- feature polygon、弧形文字、leader 通道、刻度和圆心保留区登记为同一 build 的
  物理资源；同一 track 只对应一个径向区间。feature 与 label 在相邻轨道时不画
  引线，跨过中间轨道时登记 leader 占用；明显引线应沿局部法线，不向远处倾斜。
- 标签先尝试放进自身箭头的可用 body，再试其紧邻的内侧文字轨道；仅在真实的
  字符包络冲突后进入更深的合法轨道。弧形文字逐字沿选定半径排布，但整串只判定
  一次阅读方向，不允许左右两侧的字符中途翻转。
- 同一合法文字轨上的小幅切向错位可以先于更深轨道，用于让相邻标签主动避让；
  错位代价随距离凸增，不能让文字沿圆周远走。需要指示线时，文字不必与 feature
  中点正对齐；引线仍从真实 feature anchor 出发，并裁切到最先遇到的字符包络边缘，
  不强制连接整串文字的中心点。
- 非最内层 feature 的文字不可穿越下一层箭头，也不可占用那层箭头或更深的
  label-only track；最内层 feature 可使用它内部的共享文字轨道。箭头层之间的
  走廊仅按该角区实测文字需求扩大；没有需求时保持较窄净距，不能机械地把所有
  内层箭头推向圆心。邻轨的小幅局部错位优先于远离所属 feature 的径向或切向漂移。
- 所有合法内轨都失败时，按 `external = TRUE/FALSE` 转为外部 callout 或隐藏；
  不伪装为穿层成功。外置文字也需进入最终 bbox 与画布拟合。

## 圆外注释、限制性位点和 primer

- 圆外 track 不是有宽度的环带，而是一组只约束**文字控制点**径向位置的同心圆。
  控制点可为水平文字面向 root 的起始边、名称连接点或某个 geom 明确定义的
  等价锚点。track 只规定该点在哪个半径，不要求整段文字或 bbox 被包在该轨之内；
  长文字可径向或切向跨过相邻控制点轨。
- “可出轨”不等于文字不参与布局。restriction-site、外置 feature 和独立 primer
  都必须向同一 coord-owned registry 提交真实 root、自然控制点、完整实测 bbox、
  类别特定的文字连接点与合法 leader 路径。求解器以控制点所在外轨为离散状态，
  但以整个 bbox 和完整 leader corridor 检测碰撞、堆叠和画布边界。因此两个控制点
  在不同外轨上仍可能冲突，不能用“已分轨”替代完整 bbox 判定。
- 外圈求解必须将位点、外置 feature 和 primer 作为同一有序候选序列联合求解。
  restriction 位点的基因组顺序是硬约束；feature/primer 根据自己的真实 root 极角插入
  同一序列。求解器应在保序前提下让局部控制点自动变轨，而不是先把所有位点
  锁在同一轨、再让其他 geom 向外逃离。先维持自然极角与近轨，只在完整 bbox 或
  leader 实际冲突时才局部变轨／小幅切向移动；不使用四侧笛卡尔文字墙。
- 位点 leader 从真实 backbone 边界出发，优先直线；若须折线，最多一个折点，
  表现为短根段加较长的扇出段，不画弧线或独立刻线再接两段线。密集位点与
  feature/primer 的文字和引线必须联合避让，不能先固定全部位点再让后者开花。
- `geom_primer()` 是独立注释，默认在双线 backbone 两圆之间绘制紫色方向短弧；
  `geom_primer_label_repel()` 使用同色无底框文字和 leader，默认可显示 1-based
  inclusive 区间。leader 从短弧的方向端（3′ 端）起笔。来源中的
  `primer_bind` feature 仍按普通 feature 的轨道与形状处理，不与独立 primer 混同。
- `find_restriction_sites()` 保留酶身份、切点、来源及甲基化状态；仅有来源支持的
  blocked site 加星号并使用灰色。不对未知甲基化上下文作猜测。共点位点合并，
  相邻 bp 不合并；unique cutter 与重复 cutter 的字重不同。

已实现单序列圆图主链、feature shape/stacking、弧形 feature 文字、数据来源与
primer/位点的基础几何；外圈注册表已能导出局部碰撞与引线诊断。最近的开发期
轻量检查中，pBluescript II SK(+)、pTRIPZ 和 pTRE-Tight-BI 的针对性几何导出
通过；这**不是**十三图视觉验收，更不是正式发布验收。

必须继续解决的共性问题：

1. pBluescript 的内侧 MCS/primer feature 簇仍比参考图过于靠近圆心；
   需要联合优化 feature 实体分层、箭头宽度、局部文字走廊和最近轨道选择，
   而不是全局压缩或扩大间隙。pTRIPZ 的其他 feature 文字也不得在邻轨有空位时
   无故移到深轨或圈外。
2. pTRIPZ 的六个 `tet operator` 在固定尺寸与自动尺寸专项导出中均已保留，
   但纵列间距、引线束和邻近的 TurboRFP 外置标签仍未达到参考图；
   pTRE-Tight-BI 的同类 operator 因上层
   双向 promoter 的真实层级，继续保留为内圈多轨簇。规则依局部几何和来源
   关系，不按质粒名分支。
3. pETDuet-1 已切换到 restriction、feature 与 primer 的保序联合求解；固定尺寸和
   自动尺寸专项脚本均保持 5 个 primer、跨类文字无重叠、可见 leader 无交叉，
   primer 端点也按真实文字尺度落在名称两侧而不进入括号坐标。当前人工对照仍显示
   restriction 保留率低于参考图，MCS-1/MCS-2 外置标签仍隐藏，部分 fan 的线束
   偏长，联合求解开销也偏高；因此
   几何断言通过仍不等于十三图视觉验收完成。后续应改进优先级／共点聚合和候选剪枝，

4. 对照全部十三图复核 pBR322 的局部外溢、pUC19/pBluescript 的同轨优先、

   pTRE-Tight-BI 的双头箭头、PX458 的 `capped_line`、pTRIPZ 的文字方向及

### 2026-09-24 局部候选顺序修订

- 圆内候选代价已改为：最近合法文字轨上的小幅切向错位优先于进入更深轨道，
  且错位代价随距离凸增；标签引线继续由统一 clipping 逻辑连接到首先相交的逐字符
  包络边缘。pBluescript II SK(+)、pTRE-Tight-BI、pBR322 与 pUC19 的针对性导出
  通过，pTRE-Tight-BI 的六个 operator 仍全部保留在内圈。
- 圆外候选保留各类几何语义，但对 feature callout 和独立 primer 提高了径向外溢
  代价，使同一圆轨的局部切向避让先于继续向外开新轨；restriction 仍保持原有
  紧凑扇形优先级。pTRIPZ 的六个 operator 已由远距离开花收回为靠近圆周的连续
  纵列，自动尺寸审图明显接近参考图，但引线束和纵列间距仍需继续收敛。
- 曾试验把混合扇区内的 restriction 撤出既有扇形，再与 feature/primer 顺序插回；
  pETDuet-1 的交叉记录由 5 增至 11 以上，说明这会破坏 restriction 的保序结果，
  已完整撤回，未作为实现保留。

### 2026-09-24 混合外圈路径修正

- feature/primer 移动后现在按最终实测文字 bbox 重建连续路径，并将末端
  落在面向 root 的文字边缘；候选路径缩短时，多余的几何行会收拢到最终端点，
  不再留下与主路径断开的旧坐标。feature 与 primer 在普通候选耗尽时可继续
  沿同一圆轨局部扇出，pETDuet-1 和 pTRIPZ 专项几何检查的交叉记录均降为 0。
- 带标签的 restriction site 不再同时绘制独立 tick 和两段 leader：短 tick 仅作为
  不可见的 root/collar 导出元数据，可见 leader 从骨架外边界开始，或为直线，
  或经一个保序 fan 肩点到达文字边缘。双线骨架的短出发段可使用两线之间的
  狭窄走廊，但不得进入 feature 内圈；无标签位点仍绘制原有短 tick。
  后续审图发现隐藏标记最初只存在布局导出表，未经 aesthetic mapping 进入实际 geom，
  导致成图仍画出 tick；现已修正绘制管道，并用 `ggplot_build()` 直接验证，不再仅检查
  layout export。
- primer leader 与其他圈外指示线使用相同的直线／最多单折点规则，不设置 primer
  专属路径形态。其特殊性只在文字连接语义：指示线连接 primer 名称面向 root 的
  左／右侧，括号及其中坐标放在名称外侧，不参与连接点选择。候选仍按真实圆周 root
  顺序求解，不按图层添加顺序或注释类别抢占位置。
- 这一步修正了连续性和专项几何相交，但 restriction 仍先求解、feature/primer 后避让；
  因此真正对称的局部联合候选／路径求解仍未完成，不得宣称共同外轨契约
  已经全面实现。

### 2026-09-24 外圈全局标注模型调研与重构决定

- SnapGene 的公开支持文档和版本记录只说明行为：拥挤圆图会将
  feature 标签移到圈外，无法全部显示时存在优先级，且相邻标签的布局
  曾被专门改进；未找到其具体几何模型、代价函数或求解器的公开说明。
  因此不把对参考图的观察写成“SnapGene 内部算法”。
- 现有试验实现虽统一收集 restriction、外置 feature 和 primer，但仍是
  先压缩控制角、再按字框面积逐个贪心放置、最后事后重建 leader。
  pETDuet-1 在不同设备尺寸下会出现不同交叉数，证明它不是可继续调权重
  的合格基础。该试验降级为失败原型，不放宽现有验收断言去迁就它。
- 新实现采用“径向轮廓标注 + 锁定环形顺序”的混合模型。水平文字使用
  面向 root 的字框侧边端口；全部类别共享同一轮廓上的离散候选端口、
  完整 bbox 和 leader 几何。root 环形顺序、字框不交叠、leader 不交叉、
  leader 不穿过非对应字框为硬约束；距离 root 的位移、leader 长度、
  拐点数、额外径向层级和隐藏优先级为可组合软代价。
- 最初拟在最大 root 空隙处打开环，按密集区间分段，并用动态规划／最短路
  求保序候选的全局最小代价解。实际候选存在非相邻文字框及路径冲突，简单
  相邻状态最短路不足以表达全部硬约束；目前改用分层 beam、惰性兼容缓存和
  最终完整冲突审计。这是近似求解器，不宣称数学全局最优。每个候选仍是完整的
  “字框 + 端口 + leader”原子，“外轨”仍由中选控制点半径决定。
- restriction、feature 和 primer 的类别只决定根部来源、合法连接端口、
  样式和显示优先级，不决定求解先后。primer leader 继续与其他圈外 leader
  共享路径形态；其文字端口仅位于 primer 名称两侧，括号及坐标不参与
  连接点选择。目标是在可行范围内最大化标签保留，并在导出诊断中记录隐藏；
  当前 beam 可能遗漏可行组合，因此隐藏数和计算成本仍须继续优化，不能把
  “搜索未找到”直接等同于“几何上无解”。
- 保留 coord-owned registry、实测字框、geom 独立数据／样式和最终几何回写；
  替换逐个 `ggchord_external_place()`、restriction-first 轮廓、事后
  `ggchord_reroute_mixed_external_leaders()` 及“先定文字再修线”的流程。
  布局必须按实际导出设备尺寸与字体度量重新求解，缓存键必须包含设备度量，
  不复用另一尺寸下的终端坐标。
- pETDuet-1 作为首个重构验收样本：不固定精确浮点坐标，但要求字框
  和 leader 无交叉、root 环形顺序保持、未隐藏数最大化、无事后路由，
  且人工对照中呈现参考图式的局部阶梯／扇出，而不是单一强制外轨。

### 2026-09-25 外圈联合求解器实现进展

- 已以新的 coord-owned 全局求解器替换正式调用路径中的 restriction-first
  放置。restriction、外置 feature 和独立 primer 先各自提交任务，再按 `accver`
  合并成同一环形序列；每个候选原子同时包含完整实测文字框、控制点轨道、合法
  文字端口和完整 leader，写回后还会核对实际路径与中选候选完全一致。
- 圈外文字统一按最终水平排版测量，设备换算不小于实际渲染尺度。restriction
  的复合文字框直接复用加粗酶名、普通坐标和 0.65 mm 间隙的真实度量；primer
  使用完整未换行标签参加碰撞，但合法端口只落在名称片段左右边界。左侧 primer
  显示为“坐标 + 名称”、右侧显示为“名称 + 坐标”，坐标片段始终位于外侧且不参与
  连接点计算。
- 普通圈外文字的 leader 按 root 方向进入最近矩形边界；primer 仍使用名称两侧
  端口。路径优先由短径向根段和一条扇出段组成，最多一个折点；若该折线不能保持
  在骨架外侧才退回安全直线。文字框重叠、leader 相交、leader 穿过其他文字框均为
  硬约束，控制点角顺序与真实线段平面性分别判断，不再用端口极角替代交叉检测。
- 同一切点的多个限制酶可拥有相等自然角；打开环时只有真正跨越原点才增加
  `2*pi`，相等角由保序打包形成局部 fan。复合 restriction 的隐藏状态现在同步
  控制普通 label、酶名、坐标片段和路径可见性；此前只把 `label` 设为 `NA`、但
  复合 grob 仍被画出的“幽灵标签”缺陷已经修正。
- 求解使用按隐藏数量分层保留的 beam：每个可见性层级都保存若干最低代价状态，
  防止前面的 restriction 抢占空间后才发现必显 primer 无候选。远距离任务先按
  兼容处理，近距离候选对采用惰性矩阵缓存，只计算 beam 实际访问的组合；中选解
  再做完整冲突审计，并把发现的远距离冲突加入下一轮。pETDuet-1 的固定尺寸和
  自动尺寸专项脚本现可保持 5 个 primer、跨类文字无重叠且可见 leader 无交叉；
  仍需继续提高 restriction 保留率并降低联合求解开销，不能据此宣布视觉验收完成。

### 2026-09-25 公共 API 与内部职责审计

本轮允许大幅重构，但不把尚未确认的破坏性删除伪装成已决定接口。当前结论如下：

- `ggchord()` 继续作为统一构造器；`coord_chord()`、`coord_circular()` 和后续
  `coord_collinear()` 保持独立坐标契约，不合并成带大量模式分支的单一 coord。
  跨图层物理碰撞、设备文字度量和最终轨道分配属于 coord/build；geom 只保留数据、
  aesthetic、样式、候选生成与绘制资源，Position 只保留无需知道设备的局部 lane。
- `geom_restriction_site()`、`geom_primer()`／`geom_primer_label_repel()` 和 feature
  label 继续是独立公开 geom，因为其数据契约、guide 和绘制语义不同；它们只在内部
  实现统一的 external-annotation task/candidate/writeback 协议。不得为了共同避让
  合并用户数据或新增一个包办所有注释的公开 geom。
- gene 与 feature 的区间、shape、label 和 stacking 实现应继续向同一内部核心收敛；
  现有 `geom_gene*()` 与 `geom_feature*()` 是否保留为语义便利入口，留到 v0.99.0
  依据实际使用和迁移成本决定，本版不突然删除。stat 只做数据变换，不承接设备布局；
  scale 只训练 aesthetic，不保存候选轨道或碰撞状态。
- `get_chord_layout()` 与 `export_ggchord_layout()` 的职责有重叠。候选方向是把后者
  作为稳定、带坐标空间元数据的导出接口，把前者限定为低层诊断或逐步弃用；这是
  v0.99.0 的待确认决定，本版只保证现有调用可迁移，不提前删除。
- `geom_link_*()` 与仍导出的 `scale_ribbon_*()`／`stat_ribbon_*()` 命名存在历史层级
  不一致；`scale_link_*()` 与 `scale_ribbon_*()` 也有重复。v0.99.0 应按 aesthetic
  角色、已有迁移记录和实际调用清点别名，选择单一推荐名称并给出删除版本，不能在
  v0.13.1 的视觉重构中顺手改名。
- 当前大量直接 re-export 的 ggplot2 便利函数扩大了维护面，但删除会影响用户脚本。
  v0.99.0 需区分“ggchord 文档示例便利”与“包自身稳定 API”，逐项决定继续 re-export、
  仅文档导入或弃用；不在本版批量删减。内部临时列、候选编号、beam 宽度、轨道半径
  和 registry 迭代状态均明确为非公开实现，不进入 scale/aesthetic 或稳定返回契约。

验收以实测字体与实际导出尺寸的文字/引线无可避免碰撞、标签保留率、轨道
层级、顺序、形状和人工对照参考 PNG 的整体可读性共同判断；几何计数过关
不能替代审图。开发期只做直接相关的轻量脚本与代表性渲染。只有用户明确授权
GitHub 正式发布时，才运行完整 testthat、`R CMD check`、英语/汉语 vignette
及 PNG/PDF/SVG 发布矩阵。当前没有正式发布、tag 或 Release 授权。
