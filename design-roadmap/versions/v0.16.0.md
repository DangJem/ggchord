# v0.16.0 — 定量多轨道与输出质量

**状态：计划中。**

2026-10-28 用户已授权将物理尺寸和输出调研建议纳入本版：沿骨架/法线的局部
形状协议、真实 panel 内的毫米/字号度量、内部文字的有界缩放与最小字号、
公共比例尺和选择性序列轴、完整引线/文字/实体质量诊断。实现需保留既有数值参数
的可执行迁移，不让三种 coord 共用伪半径或同一个物理 track 编号。

在 link、单序列和直线坐标稳定后，再补齐类似工具中对科研图常用但 ggchord
尚缺少的定量轨道：

- 设计统一的显式 track/ring 用户契约，不根据列名自动猜测轨道；
- 评估 coverage、GC content/GC skew、分类 tile、折线和柱形轨道；
- 数值映射继续使用 role-specific scale，轨道几何可向障碍协议注册实体范围；
- 提供色觉友好、灰度和最小字号/线宽诊断，但不强制修改用户风格；
- 对 PNG、PDF、SVG 的实际输出尺寸、字体、透明度、裁切和 guide 比例生成诊断报告；
- 交互式绘图仍留到 v1.0.0 后，v0.16.0 不恢复 Plotly 或引入 Shiny。

## 与 v0.13.1 内部轨道的关系

v0.13.1 延续的 circular annotation track manager 是 `coord_circular()` 的内部布局机制，
主要解决 feature、feature label 和 leader 的自动空间分配。v0.16.0 不将该内部
注册表直接暴露为用户 API，而是在坐标模式稳定后建立一层显式语义：

- 用户声明轨道内容、顺序、内外侧、宽度策略和 scale，而不直接依赖
  v0.13.1 的临时半径、内部列名或布局迭代次数；
- 公共层复用轨道申请、数值映射、障碍包络和导出元数据，各 coord 仍保留
  自己的物理实现：`coord_circular()` 映射为环形带，`coord_collinear()` 可映射为
  水平上下带，`coord_chord()` 只支持其几何契约明确允许的轨道类型；
- 公开契约中优先使用“轨道请求/轨道角色”而不是强制三种坐标共享同一
  编号和距离。`track` 与 `ring` 是用户级概念，半径、y 偏移和曲线法线距离
  是 coord-specific 实现细节；
- v0.16.0 需为“当前 coord 不支持某轨道角色”提供显式错误，不能静默丢弃、
  压平或伪造等价几何。

在公开 track/ring API 之前，先把 v0.13.1 已验证的内部资源协议抽象为不依赖
具体注释类别的三段式接口：geom 提交逻辑资源和合法候选，coord 按设备度量联合
分配，geom 接收中选结果并绘制。公开层只暴露稳定的轨道角色、顺序、侧别、宽度
策略和 scale；不得暴露 beam、候选 slot、内部半径步长或某个参考软件的命名。
数值轨道与外部文字控制点轨道必须是不同角色：前者拥有不可越界的物理带宽，后者
只约束控制点但让完整 bbox 参与碰撞。

v0.16.0 验收时必须分别检查各坐标系的轨道映射，而不以一组跨坐标的
精确物理坐标断言锁死实现。
