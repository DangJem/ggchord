# v0.16.0 — 定量多轨道与输出质量

**状态：计划中，未启动；2026-10-29 审计后仍独立于 v0.15.0。**

## 计划审计结论

本版同时涉及公共轨道契约、coord 资源分配和真实设备尺寸，开发压力不小，
不满足用户提出的“压力较小才合并到 v0.15.0”的条件。v0.15.0 先完善显式数据准备；
本版保留已确认范围，但按下列顺序推进，避免一次性重写布局并同时扩张轨道类型。
未验证的候选实现不得写成已经稳定的公共 API。

## 第一阶段：物理度量与内部协议

2026-10-28 已确认的沿骨架/法线局部形状、真实 panel 毫米/字号度量、内部文字的
有界缩放与最小字号仍保留。先复用现有文本测量及障碍协议，明确设备、字体缺失、
panel 尺寸未知和 coord 能力不足时的失败语义，避免再建立一套与导出不一致的尺寸系统。

在公开 track/ring API 之前，将既有内部资源协议抽象为三段式：geom 提交逻辑资源
和合法候选，coord 按设备度量联合分配，geom 接收结果并绘制。只抽象确实被多种
几何共享的部分，不为了形式一致强制三种 coord 共用伪半径或物理轨道编号。

v0.13.1 的 circular annotation track manager 仍是内部布局机制，不直接暴露临时
半径、内部列名、beam、候选 slot 或迭代细节。保留既有数值参数的可执行迁移，
公共 API 稳定前明确替代写法和删除版本，不能静默改变默认图形。

## 第二阶段：显式定量轨道

- 用户显式声明内容、顺序、侧别、宽度策略和 role-specific scale，不根据列名猜测。
- 优先以已有区间值或采样点承载 tile、折线、柱形等基础几何；coverage、GC content/
  GC skew 是数据语义与候选使用场景，不为每个指标机械增加独立 geom。
  具体公开函数及首批支持类型须在第一阶段的能力矩阵明确后确认。
- 复用轨道申请、数值映射、障碍包络和导出元数据；数值实体注册真实占用范围，
  不把外部文字控制点轨道混作数值带宽。前者只限制控制点、完整 bbox 仍参与碰撞；
  后者拥有不可越界的物理带宽。
- `coord_circular()` 映射为环形带，`coord_collinear()` 可映射为水平上下带；
  `coord_chord()` 只承诺几何契约明确允许的角色。当前 coord 不支持时必须显式错误，
  不静默丢弃、压平或伪造等价几何。
- 公共概念是轨道请求/角色；半径、y 偏移与曲线法线距离属于各自物理实现。

## 第三阶段：静态输出质量

保留公共比例尺、选择性序列轴、完整引线/文字/实体诊断，以及色觉友好、灰度、
最小字号/线宽检查。先审计既有序列轴和 role-specific scale 可复用部分，避免重复 API。
诊断只报告有依据的风险及测量条件，不自动改用户风格，也不承诺由有限规则保证
全部标签可读或所有色觉状态都可区分。

PNG/PDF/SVG 实际尺寸、字体、透明度、裁切和 guide 比例检查作为用户显式请求的
工具/报告；完整设备矩阵仅放入发布验收，不变为每次 build 或日常 testthat 的负担。
大幅正负曲率、极短弧与超密集标签压力矩阵继续保留在 `tools/` 的显式验收中，
区分合法相交、数值错误与视觉退化，不设机器无关的固定耗时门槛。

## 验收与非目标

逐一核对各 coord 的支持能力、数据保留、障碍边界和物理尺寸；只用必要的公开行为
与已确认严重缺陷回归，不用跨 coord 精确坐标、内部编号或参数组合穷举锁死实现。
日常开发只做当前阶段直接相关的局部验证，GitHub 正式发布须另获明确授权。
交互式绘图仍在 v1.0.0 后，本版不恢复 Plotly 或引入 Shiny。
