# v0.16.1 — 绘图语法与可发现性统一

**状态：计划中；尚未开始实现、验收或发布。**

本版是 API 分阶段重构的第二阶段；总安排见
[API 重构计划](../API-REFACTOR-PLAN.md)。以下范围是工作计划，具体接口去留未定。

## 前置依赖

- v0.16.0 的 API 基线、目标架构、参数台账和首批修复已经形成可追溯记录。
- 开始本版开发前，v0.16.0 必须已正式发布到 GitHub 并整合 main；再从 main
  创建 `codex/v0.16.1`。本轮不创建该分支，也不提前实施本版接口变化。
- 涉及公开命名、默认值或旧调用的变化，先形成证据、替代方案和迁移示例。

## 范围

- 逐项明确 geom、stat、position、coord、scale、guide、theme 的职责与参数归属。
- 横向比较标签命名、link/ribbon 几何参数及三坐标共有参数的含义和单位。
- 核查固定参数与映射参数的边界、`...` 透传、staged mapping 和错误行为。
- 审核 gene/feature 入口、便利 wrapper、颜色拼写别名和第三方重导出的用途；
  保留便利封装与共享实现可以并存，不以减少导出数量作为独立目标。
- 明确 `geom_seq_scale()` 与位置映射 scale 的不同职责，改善任务导向的可发现性。
- 维护同类多图层的数据、映射、参数与状态独立性，以及用户 scale 的优先规则。

## 报告问题对应

- 主要覆盖 F06、F08–F15、F19、F27–F29。
- F08 等 C 标签可以只是实现现状；H/D 项须取得证据或明确取舍后才落实变化。
- 数据含义依赖 v0.16.2、引擎实现依赖 v0.16.3 的事项应注明依赖，不制造临时特例。

## 非目标

- 不增加第四类绘图模式，不全面重写布局引擎或重建网站。
- 不因名称相似合并 gene/feature、link/ribbon，也不默认删除 color 或重导出。
- 不为缩短函数签名把参数统一藏入 `...`；不无理由改变默认配色、布局和图例。
- 新 API 仅作为有真实场景和现有能力缺口证据的候选，按总计划准入后确定。

## 交付与完成条件

- 计划在 `audit-generated/` 补齐三坐标与核心图层兼容矩阵、aesthetic 和参数职责记录。
- 计划更新 `API-ARCHITECTURE-PRINCIPLES.md`、`API-AUDIT-DECISIONS.md` 与
  `API-MIGRATION.md`；这些产物尚未由本轮规划生成。
- 每项实施变化均有前后调用、受影响场景、错误策略、弃用或删除版本及必要文档。
- 用少量代表性 build 核查多图层、不同 data/mapping、手动 scale 及图层顺序；
  仅在新公开行为或已确认严重缺陷需要时增加最小回归，不穷举参数语法。
- 完成条件是已选范围有可复核结论和验证，未定事项明确保留，不能将空栏视为完成。
- 普通开发只做相关轻量验证；完整 testthat、包检查、vignette 和设备矩阵仅在
  用户明确授权正式发布本版后执行，计划本身不构成发布授权。

## 待确认取舍

- gene/feature 公开入口是否并存；shape 双入口、标签参数及 link/ribbon 的首选命名。
- color/colour 别名及各重导出的保留价值、迁移负担和处置版本。
- 主题参数应保留、归组还是调整公开归属；任何改名、删除及默认值变化均未定。
