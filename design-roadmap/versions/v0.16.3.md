# v0.16.3 — 内部引擎与输出契约重构

**状态：2026-10-31 已从 main 创建 codex/v0.16.3，正在开发；未执行正式发布验收或发布。**

本版在公开语义与数据契约明确后整理内部阶段及状态所有权；总安排见
[API 重构计划](../API-REFACTOR-PLAN.md)。整理结构不等同于重写已正确的几何算法。

## 前置依赖

- v0.16.0 的调用与参数流盘点、v0.16.1 的绘图语法和 v0.16.2 的数据契约已可追溯。
- 开始本版开发前，v0.16.2 必须已本地开发完成并整合 main；再从 main
  创建 `codex/v0.16.3`。2026-10-31 已核对前置完成，基线为 `723575a`；
  原“本轮不创建分支”仅为旧规划记录，现按用户启动授权进入本版。
- 抽取前先建立原版与候选版可比的公开行为样例及阶段状态依赖图。

## 范围

- 盘清巨型布局函数和 `eval(quote())` 中的输入、输出、共享变量及阶段先后依赖，
  再逐步改成显式上下文和阶段函数；每批保持可回溯，不一次替换整个引擎。
- 明确每层注册、data/mapping/参数、clone、缓存与中间状态的所有权和生命周期。
- 核查圆图与线性图的 annotation registry、标签路由、link 避障及轨道布局，
  仅共享语义确实相同的内部能力，不将坐标模式差异压成隐藏特例。
- 区分数值域、轨道空间位置与设备物理尺寸，核查同 track ID 的多层声明、
  bounds、closed、baseline、分段窗口与缺测值行为。
- 整理 layout export、预览和诊断各自的职责、稳定字段、单位、来源与缓存作用域。
- 结合直接调用、S3、ggproto、字符串回调和 quote/eval 证据审查内部未用候选。
- 在有实际性能或内存退化证据后再定向优化，不以代码行数或固定秒数作目标。

## 报告问题对应

- 主要覆盖 F04、F05、F07、F18、F21、F22、F25、F26。
- F04 的隐式状态是已观察结构，并不自动证明绘图错误；其余假设须逐项核查。
- 新发现的严重正确性问题优先修复，接口命名与几何数值变化不得混在同一大改中。

## 非目标

- 不一次重写所有几何、不为结构统一改变默认视觉、不增加第四类绘图模式。
- 不公开布局候选、碰撞搜索或私有缓存字段，也不将内部字段通过测试永久锁定。
- 不凭词法零引用删除函数，不建立跨图泄漏的全局缓存，不重建整套网站。

- 计划在 `audit-generated/` 补齐内部依赖、阶段状态流、返回契约与验证记录，

  代表性公开行为比较核查数据保留、方向、碰撞和预期视觉差异。

  已选风险场景；完成条件是无已知严重状态串扰，输出稳定字段有明确承诺。
