**状态：v0.13.0 开发与本地验收阶段，尚未发布。** 专用
`coord_circular()`、通用 feature geometry、Position grammar、内置通用注释数据库
与限制性酶切数据/显示分层均已实现，正在进行开发期轻量验证；发布级回归验收待正式

[`../GGCHORD_VISUAL_REFERENCE.md`](../GGCHORD_VISUAL_REFERENCE.md) 为基础；
2026-09-13 与 2026-09-20 用户对十三张参考图的逐项反馈具有更高
优先级。restriction-site、feature 外部标签和 primer 共用同一外围注释注册表；
标签保持水平书写，但它们的起始锚点落在一个或多个同心圆外轨上，完整文字包围盒
只用于碰撞、堆叠和画布 fitting，不得为了把整段文字塞进某条笛卡尔直线栏而强制
变轨。此前 top/right/bottom/left 四侧 perimeter rail 是人工复核中的过渡实验，

## A. 单序列圆图

单条完整基因组不应只是“四序列 chord 少三条序列”的退化情况。v0.13.0 计划
提供明确的单序列布局入口，共享现有 gene/feature/region、scale、theme、guide
和标签组件，但不生成无意义的跨序列 ribbon。

- 支持闭合圆形和带缺口的线性化圆图；
- 基因、调控元件、重复区和用户 region 可放在显式内外轨道；
- 标签可选择贴弧、局部径向或外部 callout，并复用碰撞、换行和省略策略；
- 原点、方向、旋转和坐标标签由 coord/position scale 管理；
- 明确参考 SnapGene、Geneious 和 DNA Features Viewer 的信息层级与可读性；
  可直接使用第三方字体、图标、图片、专有配色及其他资产，但代码中的函数名和
  参数名保持通用，不写入第三方名称。

最小原型比较后采用专用 `coord_circular()`，由它管理缺口、原点旋转和方向；
单序列行为不放入 `coord_chord()` 的条件分支。

## B. Position grammar 与通用 feature geometry

- v0.13 起 `geom_gene()` 的默认 placement 是 `position = "identity"`；v0.12
  隐式 `gene_offset = 0.1` 的迁移写法是 `geom_gene(position = "strand")`；
- signed local-normal 统一规定正值向 sequence 外侧、负值向内侧；标量
  `position_strand(0.1)` 展开为 `+ = +0.1, - = -0.1`，显式命名的链值不再翻转；
- `position_plasmid(-0.1)` 让两条 strand 共用内侧 band，strand 仅控制箭头方向；
- `position_feature_stack(base_position = ...)` 先放置基础 band，再将 track
  作为圆内注释的显式布局层。长且高优先级的 feature 靠近 backbone，
  局部重叠对象向内分层；不重叠的相邻 feature 只在父级覆盖区间内
  可共用层，不得跨越父 feature 末端继续强制同层；
- 默认 stacking 顺序先服从显式 `display_priority`（大值优先）或
  `prioritized_display = TRUE`，然后严格按 span 由长到短分配；每个 feature
  始终选择最近的无冲突层，不再为局部相邻关系保留较深层。
  默认内侧 plasmid band 中，track 0 最靠近 DNA backbone，更深 track
  逐步靠近圆心；
- feature type、名称和颜色不得单独决定 track，不使用 AmpR、lacZα、ori
  等名称特例。但内部布局明确区分 backbone、feature band、feature-label
  gutter 和更深的 label-only track；`find_common_features()` 不输出语义
  `preferred_lane`；
- `geom_gene()` 保留 gene role、gene scale、strand guide 和专用入口，但 polygon
  由 `geom_gene()`/`geom_feature()` 共用的 interval、local frame、shape factory
  与 short-feature pipeline 产生；
- `geom_feature_plasmid()` 是该通用引擎的单质粒快捷方式；multi-segment
  feature 在 layout 与 stacking 阶段始终是一个 biological feature，共享
  track、方向和唯一 label；只在几何阶段按 segment color、gap 和局部
  分界细分，整个 feature 只在真实方向端生成箭头。连续 source segment
  的 join 默认画点状虚线，显式非实线 `line_style` 可覆盖其样式，同一位置的
  cleavage arrow 与 join 合并，避免重复描边；
- 通用 `feature_shape` 扩展为 `arrow`、`compact_arrow`、
  `promoter_arrow`、`primer_arrow`、`marker`、`block`、`capped_line`、`chevron` 和
  `lollipop`；这些是用户可显式选择的 geometry，不由 feature type 强制。
  nondirectional 默认无箭头，forward/reverse/bidirectional 则服从 feature 自身
  directionality 生成对称的单端/双端方向表达；
- zero-length/point feature 不会被放大为伪区间 polygon，而是在 DNA
  backbone 上绘制短径向 tick。极短 directional feature 围绕真实 midpoint
  建立受限的最小显示跨度，只压缩沿序列方向的 body 与 head 长度。
  所有 shape 仍保持同一名义径向 body 宽度，不再因区间较短而缩窄整个特征。
  `capped_line` 是无填充的细长区间并在两端带短端帽，用于源数据明确的
  `noColor`/线性显示语义；
  单端与双端方向都必须保留；真实 start/end 和 leader anchor 不改变。
  promoter、primer 及 compact arrow 保留
  同一拓扑且与其他 shape 共用统一径向 body 宽度；类型可以改变
  头部比例和轮廓，但不再通过变窄整个 feature 来降低视觉权重；
- SnapGene 官方[简单特征说明](https://support.snapgene.com/hc/en-us/articles/10383931485076-Create-a-Simple-Feature)
  明确提供 nondirectional、forward、reverse、bidirectional 四种方向及可自选颜色；
  其[格式说明](https://support.snapgene.com/hc/en-us/articles/10242682237588-What-is-Genbank-SnapGene-Format)
  还记录多段特征、段颜色和线形外观。故本版以源方向、区间/segment 和显式样式
  决定几何及配色，不把 feature type 名称硬编码成某一种箭头或颜色。
- 存在 feature label layer 时，feature thickness 依最终字号在有限上下界内
  调整；超长 label 不会使 feature 无界加厚，而是进入 label fallback；
- `gene_offset`/`feature_offset` 仅作为带 warning 的迁移入口，不能与非 identity
  Position 同时使用；`gene_width` 等纯 geometry 参数继续保留。

Feature label 是 feature layout 的第二阶段：track assignment → geometry →
feature-owned anchor → label collision resolution → fallback。默认依最终字体与
设备 bbox 依次选择 `inside`、`adjacent`、`external` 或 hidden；标签只可
改变 anchor、offset、内外状态和可见性，不改变 feature 的 genomic start/end/
midpoint/direction。Internal label 切向正置，其走向由文字所在半径的局部切线
决定，并按 fill 亮度选黑/白字。算法先根据 feature band 之间的真实空间建立
一个或多个固定半径的文字轨道；标签先选择半径，再按每个字符的实际前进宽度
沿该半径圆逐字排布，并分别计算字符所在位置的局部切线，形成真正弯曲的文字
基线，而不是将整段文字当成一条直线旋转或在平面中平移。布局冲突
与 leader 裁切使用同一组逐字符包络，不再使用整段直线 bbox。lane 0 与
lane 1 之间保留至少两条实测文字轨道的主走廊；更深的每两条 feature lane
之间也至少保留一条 label track，并在最深 feature lane 内侧建立共享
label-only tracks。lane 0 文字
优先进入主走廊，lane 1/2 文字优先进入特征簇内侧轨道；
只有这些内部候选全部失败才转为 external callout；明显移位的内层标签使用短
leader。External label 与 restriction-site、primer 共享最终圆外包围盒、轨道和
leader 占用，但保留各自候选位置和视觉语义。`external = FALSE`
时，内部与紧邻位置均失败的 label 会隐藏，
不再无限向圆心推移。`coord_circular(fit = "labels")` 依最终 bbox 扩展
外围边界，保证 external label 不被裁切。

### `coord_circular()` 内侧轨道契约（2026-09-13 确认）

- `track 0` 固定为 sequence backbone；从圆环向圆心依次编号为 `track 1`、
  `track 2`……。轨道数量由当前 feature polygon、feature label 和 leader 的实际
  占用共同确定，不预设固定数量；该轨道系统仅属于 `coord_circular()`，暂不扩展到
  其他坐标系；
- 轨道是布局资源而不是等距辅助线。各轨道可有不同径向宽度：容纳箭头或 block 的
  feature track 依该轨道最厚的实际 polygon 确定宽度，label-only track 依最终字体
  bbox 确定较窄宽度，leader 穿越的轨道也必须登记占用；
- feature polygon 优先使用靠外的可用轨道。标签若能安全放入箭头的条形 body，
  与 polygon 共用同一轨道；可用长度必须扣除三角箭头头部、两端 padding，并乘以
  保守的容纳阈值（当前默认 `0.90`），不能用包含箭头尖端的整个 feature span
  冒充文字宽度；
- 放不进 polygon 的标签优先进入该 feature 紧邻的内侧轨道，所有圆内 feature
  标签仍逐字符沿其所在轨道半径形成弧形基线。只有同一局部角区发生 bbox 冲突时，
  才继续使用更内轨道；不得先把标签沿切线推到远离所属 feature 的位置；
- feature 与 label 位于相邻轨道时不画 leader。若 feature 在 `track i`、label 在
  `track j` 且 `j > i + 1`，leader 必须贯穿并占用 `track i + 1` 至
  `track j - 1`，同时参与后续标签/leader 冲突检查；导出布局必须同时记录
  `feature_track`、`label_track` 和 leader 穿越的轨道范围；
- 当前 `position_feature_stack()` 的 lane 与 feature-label 求解器已经能够生成
  feature band 和若干文字半径，但此前只是两个阶段各自推导的局部轨道，并非
  `coord_circular()` 统一拥有的完整注册表。本轮先统一圆内物理 track 编号、
  相邻关系和 leader 判定；可变宽注册、leader 预占与跨图层统一求解仍须在
  v0.13.0 发布前完成，不得把当前过渡实现描述成完整轨道系统。

### 圆形轨道职责与实装路线（2026-09-13 确认）

`lane` 和 `track` 是两个不同层级的概念，后续实现和布局导出不得混用：

- `lane` 是 Position 层的局部分层结果。`position_plasmid()`、
  `position_strand()` 和 `position_feature_stack()` 负责表达内外侧、基础偏移、
  重叠 feature 的分组/顺序和偏好 lane；它们可以在每个局部 band 内从
  lane 0 重新编号，不代表全局半径，也不承诺最终物理间距；
- `track` 是 `coord_circular()` 拥有的全局物理资源。圆形坐标收集
  backbone 边界、各图层 polygon envelope、最终字体 bbox、leader 穿越范围和
  圆心保留区，然后将局部 lane 映射到唯一的 `track 0..n`、实际宽度和半径；
- geom 只声明形状包络、文字尺寸、anchor 和样式需求，并使用 coord 返回的
  实体位置绘制；不在单个 geom 中自建与其他图层不可见的轨道表；
- position scale 继续负责 breaks、labels 和 transform，theme 负责字号、颜色、
  线宽和物理间距；刻度和文字如何映射到内环、切线和圆周方向，由
  `coord_circular()` 的 axis strategy 负责；
- sequence backbone 的 single/double/band 轮廓和宽度仍是 `geom_seq()` 的几何/样式
  契约，但它必须向圆形坐标注册内外边界，供坐标轴、restriction-site
  和 track manager 使用，不得再默认中心线等于可见边界。

v0.13.0 仅实现不公开的 circular annotation track manager，按以下阶段落地：

1. 建立 coord-owned 注册表，统一记录 `kind`、`owner/layer_id`、逻辑 lane、
   径向宽度、内外边界、最终半径和局部角区占用；
2. 将 feature polygon 的局部 lane 映射为全局 feature track，再按实测字高插入
   可变宽 label-only track，而不在 label solver 中创建任意半径；
3. 依次解决 inside、相邻内轨、更深内轨和 external；leader 先登记需穿越的
   中间 track，再参与后续标签与 leader 的冲突检查；
4. 将同一注册结果交给 feature label、坐标轴、圆心保留区与几何 fitting，
   但 restriction-site 的圆外极坐标轮廓仍保留独立排版器，只注册其可见障碍；
5. `export_ggchord_layout()` 同时导出局部 `lane`、全局 `track`、轨道边界与
   leader 占用范围，使调试与验收不依赖精确浮点坐标。

外侧注释与内侧轨道共用同一个 coord-owned annotation registry，但使用两套
不同的物理分配器。内侧 allocator 是严格的同心环带：从 backbone 向圆心登记
可变宽 feature band、弧形文字环、leader corridor 和 axis reserved band；含箭头或
block 的轨道按 polygon 实测厚度加宽，纯文字轨道按最终字高收窄；两个 feature
轨道之间必须为文字换轨和垂直 leader 留出足够走廊。文字逐字符沿选定半径形成
弧形基线；leader 沿局部法线穿越中间轨道并登记占用，不能用倾斜长线替代。

外侧 allocator 也是同心圆锚点系统，但外侧文字本身保持水平。每个标签由靠近文字
起始字符的锚点确定所属外轨半径；文字其余部分允许自然伸出该圆形轨道。主外轨先
尝试保留真实位点的自然极角和基因组顺序，只有完整实测 bbox 与既有标签或 leader
冲突时，才把该局部标签连续移到相邻外轨。不得把完整文字框约束在某个矩形 rail，
也不得为了“整齐”把顶部、底部标签排成横行或左右标签排成竖墙。外侧对象导出
`region`、`sector`、`band`、`slot`、锚点半径、最终 bbox 和 `leader_corridor`；
其中 `band` 表示圆形锚点轨，不表示文字框必须位于某个环带内部。

`geom_feature_label_repel()` 与
`geom_restriction_site()` 仍分别拥有文字样式、候选位置和 leader 语义；
`coord_circular()` 汇总两者的最终 bbox、角区、外侧 band/slot 和 leader
通道占用，仲裁跨图层冲突。限制性位点保持基因组顺序、靠近圆周的自然扇形；
稀疏 feature callout 可保持径向或折线式布局，密集 feature callout 才在不改变
anchor 的前提下转入更外 band/slot。不把所有对象强制合并成同一左右直角坐标栏，
也不由 Position 解决跨图层设备 bbox 冲突。十三个参考图分别覆盖稀疏径向、密集
MCS 扇出、外侧 primer callout 和混合 feature/restriction 簇，验收时按这些布局类别
比较，不设置质粒名或标签名特例。

本版验收条件：Position 在不知道设备尺寸或其他图层的情况下仍可稳定输出
逻辑 lane；更改字号、feature 宽度或同类图层数量后，只由
`coord_circular()` 重新分配物理 track；任一 `track` 编号在一次 build 中唯一对应
一个径向区间，且不存在绕过注册表的 feature/label 自建半径。

当前实现状态：`CoordCircular` 已负责生成 build 级 annotation registry，结果由
当次 build layout 持有，避免不同 plot/build 之间共享可变状态；该 registry 是
圆内最终物理 track 与圆外 region/sector/band/slot/bbox/leader corridor 的统一
导出事实。圆内同一 Position lane 的不同 polygon 会合并为唯一可变宽 band，
track 0 记录 backbone 可见内外边界；restriction-site 先在主圆形锚点轨按基因组
顺序和实测切向占用排布，局部碰撞标签才连续进入相邻外轨。feature 与 primer
随后在同一 coord-owned 障碍表中选择圆形锚点轨和局部 slot，不得覆盖既有文字框
或 leader；三类标签不得被改写成四侧笛卡尔栏。
导出记录 `annotation_class`、`dominant_band`、
`band`、`spill_reason` 和 `leader_crossing_count`。

### 2026-09-19 Circular annotation registry 阶段实装

- `CoordCircular` 新增内部 registry 解析入口；每次 build 统一产生
  `side/kind/owner/component/source_row`，不使用质粒名、feature 名或颜色特例；
- 圆内将 Position `lane` 与实际 polygon envelope 分离：同 lane 的形状差异取最大
  径向包络，映射为唯一 `physical_track`、`track_radius`、`track_inner` 和
  `track_outer`；backbone 是 track 0，axis reserved band、弧形 label track 与跨轨
  leader corridor 进入同一注册表；
- 圆外不使用内轨镜像。restriction-site 的自然极角与局部扇出候选保持
  不变，feature callout 只在与已登记 bbox 冲突时外移；最终统一导出
  `annotation_region`、`annotation_sector`、`annotation_band`、
  `annotation_slot`、bbox 和 `leader_corridor`，其中 slot 在所有外侧图层之间
  全局编号；
- `export_ggchord_layout()` 对 circular 结果新增 `annotation_registry`，同时将
  对应的内侧 track 或外侧分配字段附着到 feature/label/restriction 几何行；
- 已完成 pBluescript 多 lane 圆内代表 build 和混合 feature/restriction 簇的轻量
  几何断言：一个物理 track 只对应一个径向区间，外侧最终 bbox 无跨图层
  重叠。未运行整包 testthat、vignette、`R CMD build/check` 或完整设备矩阵。

### 2026-09-23 内圈走廊按需分配的再次修订

用户对 pTRIPZ 与 pBluescript II SK(+) 指出，上一轮固定扩大的箭头间距
使空闲的外层走廊过宽，反而压缩最内层文字空间；径向轨道的绝对优先级
也让本可在相邻轨道轻微错位的文字跑向更深处。此补充明确取代此前
“第一箭头间隔无条件容纳两条文字轨”的固定最小宽度解释：每个箭头间距
应按该层实际无法放入自身箭头的文字及局部密度估计需求，仅在确有竞争时
增宽；文字求解按最近可用轨道和小幅局部错位优先，之后才尝试更深的合法
轨道。上一轮确定的“不能穿过下一层箭头”边界继续有效；若合法走廊都放不下，
才按外置／隐藏契约处理。当前实现依据实测标签宽高、feature 弧长和局部
圆周重叠估算走廊需求，仍需以十三图视觉复核来验证估算是否足够准确。
深层箭头之间若无标签需求，只保留较窄的边缘净距；这使
pBluescript 的 MCS/primer 内侧簇稍向外回收，但与参考图的半径及文字

相同名称、同一最外 feature lane、在窄角区连续重复至少四次的短标记
作为一个簇决定标签去向：整组交给外轨求解，不让单标签贪心搜索产生
“部分挤在内圈、部分飞到外圈”的混搭。pTRIPZ 的 operator 阵列与
pTRE-Tight-BI 被更外层双向 promoter 覆盖的 operator 阵列应分别验证为
外置簇与内层多轨簇；判定条件基于层级、重复与角密度，不使用名称特例。

## C. 限制性酶切位点

计划拆成数据计算和几何表达两层：

```r
sites <- find_restriction_sites(sequence) |>
  filter_restriction_sites(set = "unique_6plus")

ggchord(seq_data, gene_data = gene_data) +
  geom_seq() +
  geom_restriction_site(data = sites)
```

- `find_restriction_sites()` 只进行搜索和切点计算，返回稳定 pattern identity、
  酶名、识别序列、1/2/4/unknown cleavage、切割位置、末端类型及来源；
- 酶数据库版本必须可追踪，用户也可传入自定义 motif；
- `filter_restriction_sites()` 独立处理 unique、长度、供应商、窗口等显示筛选；
- 已知参考序列还可用 `set = "reference"` 复用源 `.dna` 保存的酶集名称
  与 custom enzyme list；该入口仅在序列精确匹配且存在参考 profile
  时可用，不将未知序列猜测为某个参考酶集。内置 preset 的父酶目录仍由
  `parent_set` 明确指定，因为这是软件全局偏好，不一定写入序列文件；
- `geom_restriction_site()` 在单个 geom 中负责刻线、标签和指示线；
- 真实位点只决定 anchor，文字位置由实际 bbox 驱动的混合排版器决定；
  稀疏标签保持自然径向轮廓，侧面密集簇自动切换为共享内边界、固定行距的
  stacked label column，并严格保留 genomic order；
- leader 在条件合适时直接连接，密集或分流标签使用独立的径向 stub
  和 fan segment 两段折线；密集簇先以短根段形成窄线束，再有序展开，
  不共享主干；
- leader 始终连到酶名所在的左/右文字边缘：向右走时连左缘，向左走时连右缘；
  接近垂直时使用该侧最近的左下/右下（或左上/右上）角，不改接上/下边中心；
  酶名自动放在接线一侧；
- 可按酶、切割次数和窗口过滤，重复名称仍保留全部位点；
- 默认复合标签用两个同一 bbox 管理的 grob 渲染：仅 unique cutter 的酶名使用粗体，
  重复切割的酶名与坐标使用常规字重；
  只合并真正同一切点，相邻 bp 始终保持独立；
- 序列搜索优先使用轻量实现；大型序列可选用 Biostrings，但不设为强制依赖。

计算层必须使用零宽匹配枚举 IUPAC motif 中可重叠的固定 anchor，
不得因 `gregexpr(..., fixed = TRUE)` 的消耗式匹配漏掉候选位点。
保留 REBASE motif 的源大小写，并在计算前将小写标记的反向切割定义
统一到标准的 top/bottom cut 方向。
`misc/embossre.equ` 作为可审计的同等酶映射纳入内置数据库；
`filter_restriction_sites(parent_set = "commercial_nonredundant")` 在 commercial
集合内按识别组和位点保留稳定代表，但不修改原始匹配或切点。

当前 REBASE 609 parser 的规范化主表读取 `VERSION`、`embossa_e.txt`、
`embossa_r.txt`、`embossa_s.txt` 和 `misc/embossre.equ`。发布包内置由这些文件可重复生成的
规范化模式表，并保留版本与来源元数据。`examples/rebase/misc/` 已解压，
其他文件保存 REBASE 的补充信息；构建或更新数据库时可按需用于补充或核验
元数据，但当前已生成数据库的运行时搜索不依赖该目录。

13 张视觉参考不能默认共用同一酶筛选链：大多数 `.dna` 保存
`Unique 6+ Cutters`，pTRIPZ 保存 `Unique Cutters + BamHI`，PX458 保存
`BbsI + EcoRI`。pETDuet-1 的 `.dna` 保存 `None`，但已检入 PNG 明显包含
密集限制性位点；这是源文件与视觉基准的事实冲突。验收脚本仅对
pETDuet-1 显式使用 PNG 所需的 `unique_6plus` 覆盖，不篡改或伪称这是
从 `.dna` 恢复的设置。

## D. Backbone、标签、主题、scale 与示例体系

- `geom_seq()` 增加 single/double/band backbone；
- `geom_feature_label()`、`geom_feature_label_repel()` 复用 gene label 的文本测量、
  碰撞、leader 与 fitting；默认 feature 模式依据最终字体 family、face、字号、
  lineheight 和设备实测 bbox，依次选择 `inside`、`adjacent`、`external`
  或 hidden，并在
  layout export 中公开 `feature_label_mode`；
- feature 标签使用统一的切向正置规则；放不下时先沿局部切线按基因组顺序错层，
  再搜索有限的相邻径向 lane，然后转为 external。求解器同时避开已放标签、
  实际 feature polygon、圆心保留区和 backbone 边界，只对明显移位的
  adjacent/external 文字绘制裁切到真实 bbox 的

### 权威实体与字段职责

- 一个不可变的 source release/provenance 记录标识工作簿、SnapGene 版本、源 `.ftrs`
  SHA-256、工作簿 SHA-256、export/import format、总序列长度和各实体计数；
- `Feature` 版本记录只保存 source-local ID、name/type、directionality、detectionMode、
  translationMW、readingFrame、cleavageArrows、allowSegmentOverlaps、编号/翻译属性、
  originalName/originalSequence、isFavorite、geneticCode、hitsStopCodon、run-on 属性和新版
  `prioritize` 等 feature-level 属性。新版实际有一条 `mini-white` gene 的
  `prioritize = TRUE`，该字段不是空占位；
- `segment_count`、span bounds、span/standard/gap length 可作为经校验的派生摘要，
  但 exact structure 只来自 1:N `Segments`。坐标语义固定为 1-based inclusive；
  `start_min_1based_inclusive`/`end_max_1based_inclusive` 仅为整体 span bounds，不能替代
  segment；
- `standard` 与 `gap` 都是正式 segment。gap 保留顺序和长度，但不进入 biological
  nucleotide sequence。新版共有 40 个 gap、174 个 multi-segment feature，最大
  segment 数仍为 14；
- `SourceSequence` 在每个 source release 中逻辑上是一条 backing sequence。Excel 的
  1,000 bp 或 10,000 bp chunk 只用于表格承载，不形成 sequence entity。top-strand DNA
  由 standard segment 坐标按 segment order 从 backing sequence 提取；reverse feature
  的 biological 5'→3' DNA 再取反向互补。旧表 1,273 条记录均可用这一关系复算其
  `reference_dna_top_strand`；
- `Qualifier` 以 `(source_feature_record, qualifier_name, value_index)` 标识一个 value，
  分别保留 `text`、`int`、`predef`、`bool` 和 `value_display`。`value_display` 是展示结果，
  不是对 typed components 的替代；新版仍有 5 个 `text + predef` 复合值；
- `QualifierLink` 以 qualifier value 加 `link_index` 标识 occurrence，保留 occurrence
  order、`anchor_text` 和 URL。不得按 URL 去重；新版 548 个 occurrence 中存在同一
  qualifier value 内同一 URL 出现三次的真实记录；
- translated status、translation qualifier、feature `type` 和 `detectionMode` 是四个
  独立维度。新版 250 个 `exactProteinMatch` 中 242 个为 CDS、8 个为
  `sig_peptide`；不得建立 `exactProteinMatch == CDS` 或“可翻译即 CDS”的约束。

### 类型变化与版本迁移语义

- 新版加入 `sig_peptide` 18 条与 `propeptide` 1 条，移除已无实例的
  `polyA_site`；CDS、promoter、protein_bind 等内容也有真实增长。Feature type 词表应
  来自 source data/派生汇总，不用旧版固定枚举拒绝新类型；
- 旧版多个 signal sequence 从 CDS 重分类为 `sig_peptide`；`tPA signal/pro sequence`
  拆为 `tPA signal sequence` 与 `tPA propeptide sequence`；两条 β-globin poly(A)
  从 `polyA_site` 重分类为 `polyA_signal`；`Csy4 site` 规范为 `Csy4 Site`。这些分别是
  reclassification、split 和 rename，不应误记成互不相关的 delete/add；
- `recentID`、工作簿 `feature_id`、name 和 type 都不是跨版本 stable identity。0–1272
  的共同 recentID 范围没有任何一条仍对应相同 name；name/type 多重集也同时存在
  15 个旧形式消失和 196 个新形式出现。当前将 `feature_id` 直接作为
  `common_feature_id` 的做法只能表示 source-local record，不能承担长期 identity；
- 后续模型必须分离稳定的 ggchord identity、不可变的 source-version feature record
  和跨版本 correspondence。correspondence 是可多对多的，并显式记录
  `unchanged`、`modified`、`renamed`、`reclassified`、`split`、`merged`、
  `added`、`removed` 或 `unresolved`、证据和置信度；一个 source record 不因映射到稳定
  identity 而被覆盖；
- 匹配证据按 source-independent biological/structural 内容组合判断：ordered standard
  segment DNA、gap 位置与长度、directionality、translation、segment translated 状态、
  qualifier typed values、detection 属性和其他 feature-level 属性；规范化 name/type 只作
  辅助证据。先在重复 name group 内作一对一候选分配，再判断剩余 variant；不能用首个
  name match 或散列碰撞式自动去重。拆分/合并使用一对多或多对一 lineage，模糊候选保持
  `unresolved` 供人工审计；
- 新版是当前 biological source of truth；旧版记录保持只读 provenance，用于说明哪些
